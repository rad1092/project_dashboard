# 데이터 흐름

이 프로젝트는 정제된 전처리 CSV를 기본 입력으로 사용하고, 실시간 재난문자 데이터는 별도 CSV로 연결하는 구조입니다.

## 1. 앱이 직접 읽는 기본 데이터

앱은 기본적으로 저장소 내부 `preprocessing_data/preprocessing/`의 CSV를 읽습니다.

- `danger_clean.csv`
  - 재난/특보 관련 기본 데이터
- `final_shelter_dataset.csv`
  - 통합 대피소 데이터
- `earthquake_shelter_clean_2.csv`
  - 지진 대피소 데이터
- `tsunami_shelter_clean_2.csv`
  - 지진해일 대피소 데이터

필요하면 `.streamlit/secrets.toml`의 `preprocessing_data_dir`를 통해 다른 경로로 바꿀 수 있습니다.

## 2. 실시간 안내용 재난문자 데이터

실시간 안내 페이지는 `preprocessing_code/data/disaster_message_realtime.csv`를 읽습니다.

이 파일은 두 방식 중 하나로 준비됩니다.

### 실데이터 흐름

1. `preprocessing_code/crawling.py`가 Selenium으로 재난문자 사이트를 수집합니다.
2. 수집 결과가 재난문자 CSV 스키마에 맞는 DataFrame으로 정리됩니다.
3. `pages/2_실시간_대피_안내.py`가 해당 데이터를 읽고 정규화한 뒤 최근 경보와 추천 결과를 구성합니다.

### 모의데이터 흐름

1. `preprocessing_code/mock_disaster_message.py`가 지역(`sido`, `sigungu`)을 입력받아 모의 재난문자 1건을 생성합니다.
2. 생성 결과를 `preprocessing_code/data/disaster_message_realtime.csv` 형식으로 저장합니다.
3. `pages/2_실시간_대피_안내.py`는 실데이터와 같은 로더를 사용해 그대로 읽습니다.


## 3. 화면별 연결 관계

### `app.py`

- 기본 CSV를 읽어 홈 화면의 요약 지표와 최신 정보 표시를 만듭니다.
- 다른 페이지에서도 재사용하는 공용 데이터 접근 흐름의 기준점 역할을 합니다.

### `pages/1_대피_안내_시뮬레이션.py`

- 정적 경보/대피소 CSV를 바탕으로 사용자가 선택한 조건에 맞는 대피소 후보와 이동 경로를 계산합니다.

### `pages/2_실시간_대피_안내.py`

- 재난문자 CSV를 읽어 컬럼 검증, 시간 파싱, 시군구 정규화, 재난 그룹 매핑을 수행합니다.
- 이후 최신 경보를 선택해 대피소 추천과 경로 안내에 연결합니다.

### `pages/3_데이터_분석.py`

- 정제 CSV를 다시 집계해 재난 분포, 지역 비교, 차트 시각화를 구성합니다.
- `preprocessing_code/shelter_type_layer_map1.html`을 권역 대피소 지도 뷰에 임베드합니다.
- `preprocessing_code/data/Emergency_shelter.db`를 참조해 일부 분석용 보조 정보를 읽습니다.
